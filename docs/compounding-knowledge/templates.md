# Draft templates
## Article metadata
Stable ID, title, summary, audience, tags, author, status (draft/reviewed/superseded/retracted), canonical source and revision, reviewed date, license, media provenance, publication approval. Existing mindblank:true opt-in is mandatory for public vault projection; never set it automatically. Use synthetic examples for private projects.
## Article body
Problem, pattern, when to use, when not to use, workflow, example, verification, pitfalls, canonical references, revision history.
## Project profile
Product promise, audience, description, feature/outcome map, repository and dependencies, architecture, specs and ADRs, milestone/goal map, visual identity (logo, icons, art), storyboards, accessibility, tests and evidence, analytics, installation, packaging/distribution, deployment/rollback, docs, demo, QA/dogfood, support and changelog. Each field has status, evidence link and owner; N/A requires rationale and substitute evidence where relevant.
Internal profile is default. Public projection explicitly allowlists fields and approved assets. Do not publish private links, topology, credentials, transcripts or private screenshot contents.
These are candidate templates; extend existing MFD companion rather than creating a competing schema.
